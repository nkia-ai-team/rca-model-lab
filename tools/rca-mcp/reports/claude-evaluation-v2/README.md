# RCA 재평가 결과 — blind v2

2026-09-11. 모델 Claude Opus 5 CLI, 45개 캡처(고유 시나리오 35종).
원본: `runs/claude-opus5-blind-v2-20260910`.

## 핵심 결과

**작성자 메타데이터의 주입 의도 대비 원인 적중은 8/45(17.8%)에서
21/45(46.7%)로 증가했다.** 부분 적중은 정답에 합산하지 않았다.

| 판정 | 이전 | 재평가 |
|---|---:|---:|
| 원인 메커니즘·위치 적중 | 8 | 21 |
| 부분 국소화/일부 원인 적중 | 16 | 19 |
| 기준과 다른 원인 채택 | 17 | 4 |
| 원인 판단 보류 | 2 | 0 |
| 기준·관측 충돌로 재심 필요 | 2 | 1 |

모두 정상 종료한 trajectory와 result.json이 있다. JSON 앞 설명 문장 때문에
추출이 실패했던 4건은 원문 변경 없이 복구했다. 포트 충돌 24건은 Docker가
빈 포트를 배정하도록 바꾼 뒤 재실행을 완료했다.

확정/잠정은 정답 판정과 다르다. 새 결과의 confirmed 11건은 match 5/partial 6,
provisional 34건은 match 16/partial 13/wrong 4/disputed 1이다. 잠정 판정이
많아졌다는 이유만으로 성능 저하 또는 정확한 확신 보정이라고 단정하지 않는다.

정답 개선과 별개로 효율·페이지 이동을 후속 검토해야 한다.

## 잘된 부분과 남은 부분

- DB 잠금, 외부 결제 429/timeout, Redis 중단→DB fallback 식별이 개선됐다.
- F18-P는 outbox relay 중단, F23-R은 재고 보충 중단을 식별했다.
- F15-G 두 캡처와 F15-H는 두 독립 원인을 함께 식별했다.
- F04-R은 소비 중단을 찾지 못했다. 회복 구간을 포함하는 집계의 소비 건수를
  보고 중간 구간의 소비 중단을 배제할 수 없다. 시간 버킷별 발행/소비·공백·
  backlog 비교가 필요한지 실제 원자료와 도구 계약을 대조해야 한다.
- F09-H는 heap/GC 문제 대신 트래픽 급증을 채택했다. F05·F09-P·F12-H의 일부도
  probe/메모리/CPU 제한 변경을 구체적으로 입증하지 못했다. 당시 설정 이력이
  캡처에 있는지와 도구로 노출되는지를 구분해야 한다.
- F06-H는 payments 잠금을 찾았으나 CREATE INDEX를 root로 연결했다. 세션과
  SQL의 시간·식별자 연결을 점검할 후보이며, 이 보고서만으로 도구 결함 확정은 아니다.
- 동명 mock의 namespace 오귀속과 F15-T1 독립 원인 일부 누락이 남았다.
- F20-R은 주입 의도가 latency-only인데 실제 응답에 PostgreSQL OOM/재시작이
  관측되어 disputed로 유지했다. 메타데이터를 무조건 정답으로 강제하지 않는다.

## 비노출과 평가 범위

45개 모두 시나리오 ID 대신 관측 알람 seed가 제공됐다. 기존 노출 검사기의
명시적 시나리오 이름/주입 명령 패턴은 새 tool_result에서 0개 케이스에 일치했다.
이 검사는 모든 간접 정답 단서가 사라졌다는 인증이 아니다.

예를 들어 F05-P의 python 메모리 할당 코드와 RSS, F10-H의 fio I/O 작업과
디스크 지표는 process_snapshot 응답에 남아 있다. 이는 수집된 운영 프로세스
관측이며 실험 설명 메타데이터와 구분해 유지했지만, 합성 장애에서 얼마나
직접적인 답 단서로 작용하는지는 별도 민감도 검증 대상으로 남긴다.

이전 명시적 노출 2개(F03-H/F05-P)를 양쪽에서 동일하게 제외한 43개 비교는
기존 7건 적중, 새 20건 적중이다(16.3% → 46.5%). 제외된 집합 외의 케이스가
완전히 누출 없음을 뜻하지 않는다.

판정 기준은 이전 rubric.md와 동일하다. 세 평가 작업이 새 결과 15개씩을
전체 metadata와 전체 result로 읽었으며, 이전 개별 판정을 읽기 전에 새 판정을
작성했다. 동일 케이스 다중 평가자 합의 점수는 아니다. 각 근거는
verdicts-01/02/03.json, 통합은 reference-evaluation.json, 비교는 comparison.json.

seed·대상 검색·시간 처리·보존 설정·필터가 함께 바뀌었으므로 개선 폭을 특정
도구 하나의 효과로 귀속할 수 없다. 메타데이터 대비 사후 의미 평가이고
검증된 observability golden이나 반복 실험 신뢰구간이 없다. 전체 grounding은
not_assessed이며, 46.7%를 공식적인 완전 블라인드 benchmark 정확도로 부르지 않는다.
