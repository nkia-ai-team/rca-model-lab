# Claude Opus 5 RCA 배치 사후 평가

평가일: 2026-09-10. 대상: 45개 캡처, 고유 시나리오 35종.
모델 재실행 없이 보존된 최종 보고서와 작성자 시나리오 메타데이터를 비교했다.

## 결론

**주입 의도 기준 엄격 적중률은 8/45(17.8%)다.** 이는 현재 실행 조건의
사후 의미 평가이며, 정답 비노출과 캡처 관측 계약을 검증한 공식 benchmark
정확도로 해석해서는 안 된다. 부분 적중을 정답률에 합산하지 않았다.

| 판정 | 케이스 | 비율 |
|---|---:|---:|
| 원인 메커니즘·위치 적중 | 8 | 17.8% |
| 부분 국소화/독립 원인 일부 적중 | 16 | 35.6% |
| 채택 원인이 기준과 다름 | 17 | 37.8% |
| 원인 판단 보류 | 2 | 4.4% |
| 기준과 관측 충돌로 재심 필요 | 2 | 4.4% |

- 실험 단서 노출이 확인된 F03-H/F05-P를 제외하면 7/43(16.3%). 나머지
  43개가 누출 없는 케이스라는 인증은 아니다.
- 기준 충돌 2개만 분모에서 빼면 8/43(18.6%). 분모 변경을 명시해야 한다.
- 재캡처의 중복 가중을 줄여 35개 scenario_id별 적중률을 동일 가중 평균하면
  19.5%. 전체 캡처 기준 17.8%와 다른 지표다.
- Claude가 confirmed라고 한 20개 중 match는 5개, partial 10개, wrong 4개,
  disputed 1개다. confirmed 수를 성공 건수로 세면 안 된다.

## 판정 근거와 대표 패턴

세 평가 작업이 각각 15개씩 전체 scenario_metadata와 전체 result.json을
읽었다. 동일한 rubric.md를 적용했고 통합 시 케이스 누락·중복·허용 판정·
분모 계산을 검증했다. 각 판정의 근거와 원문 경로는 verdicts-01/02/03.json,
통합본은 reference-evaluation.json에 있다. 동일 케이스를 여러 평가자가
독립 채점한 합의 점수는 아니며 경계 판정은 재검토 가능하다.

- F01-R/F06-H: DB lock 위치와 메커니즘을 식별해 적중.
- F04-H/F04-R: 비동기 발행·소비 중단 대신 동기 경로의 부하 증가를 원인으로
  채택했다. HTTP 성공·트래픽 증가가 무음 장애 조사를 가리는 패턴이다.
- F06-P 재캡처 중 1건은 429를 적중했지만 다른 캡처는 무관한 DB 지연을
  채택했다. 시나리오 하나의 결과를 다른 캡처로 일반화할 수 없다.
- F15 다중 원인: 한 원인을 찾고 독립적인 다른 원인을 놓쳐 부분 적중.
- F17-P: 정상 검증 경로의 400 거절을 오류로 해석하고 우회 경로의 검증
  누락을 놓쳤다. 기능적 무결성을 latency/error만으로 판단할 수 없다.
- F18-P: outbox relay의 control-table gate 중단을 식별했다. 메타의 cause는
  env/bean 설명, injection_summary는 control UPDATE라 서로 달랐다. 판정은
  후자의 실행 설명을 사용했고 이 선택을 개별 근거에 기록했다.
- F20-R: 의도는 full scan으로 인한 latency-only 장애인데 실제 반환 근거는
  postgres OOM/restart/CrashLoop를 포함해 disputed. F01-P d691440c도 참조의
  10초 lock 대기와 즉시 connection-refused 관측 차이를 재심 대상으로 남겼다.

## 함께 드러난 실행·도구 문제

1. **정답 단서 노출:** F03-H의 시나리오 파드명, F05-P syslog의 memhog 실행
   인자. metadata 파일을 숨기는 것으로 충분하지 않았다.
2. **과거 시간 처리:** 39개 케이스의 breakdown_endpoints 211회가 실행 날짜
   기준 TTL 때문에 기준선 비교를 껐다. 복원 데이터는 남아 있을 수 있는데
   time.Now()로 조회를 차단하므로 변화 탐지 비교가 훼손될 수 있다.
3. **초기 조사 입력:** seed는 case/scenario ID와 주입 시간만 포함했다.
   초기 restore.log 45개 모두 incidents=0/members=0. 제품 알람·증상 대상에서
   시작한 평가가 아니며, 원인과 무관한 신호로 출발하기 쉽다.
4. **기본 시각 미전달:** MCP는 firstEvent/lastEvent를 zero로 생성했다.
   호출자가 명시하지 않은 시간·기준선이 캡처 구간을 벗어날 수 있다.
5. **도구 오류·결측:** 1,613회 호출에 tool error 29회(1.8%), backend_error
   3회. unknown 148회, 표시 절단 271회. 반복·실패 원인은 별도 분류해야 한다.
6. **근거 연결:** evidence refs 668개 중 반환 refs와 정확 일치 591개(88.5%).
   나머지 77개는 생략·재작성·오인용을 구분해 확인해야 하며, 591개의 내용이
   결론을 지지한다는 뜻도 아니다.

이 결과만으로 모델 추론 문제와 도구 결함의 기여율을 수치로 분리할 수 없다.
우선 실험 단서, replay 시간/TTL, 초기 seed를 교정한 뒤 같은 캡처로 비교해야
개선 효과를 해석할 수 있다. 운영 텔레메트리 원본은 보존하고, 실험 전용
이름/명령만 식별·격리해야 한다. 실제 OOM/SQL/프로세스 관측을 지우면 안 된다.

## 재현

```sh
python3 scripts/diagnose_claude_trajectories.py runs/claude-opus5-all --out reports/claude-evaluation/tool-diagnostics.json
python3 scripts/aggregate_reference_verdicts.py
```

의미 판정은 사람이 읽을 수 있는 근거를 가진 평가 기록이다. 집계 스크립트는
그 기록을 검증·집계하며 키워드로 정답을 자동 판정하지 않는다. 원본 45개
result/trajectory는 이번 사후 평가에서 수정하지 않았다.
