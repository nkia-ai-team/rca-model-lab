# RCA 사후 평가에서 확인된 도구 결함 수정

2026-09-10. 사용자가 요청한 시간 처리 → 대상 발견 순서의 수정이다.
기존 45개 실행·평가 파일은 그대로 두며 본 변경으로 정확도가 개선됐다고
주장하지 않는다. 정답 단서 격리·근거 드릴다운·기능적 장애 조사는 별도 남은 작업이다.

## 기준선

breakdown_endpoints는 요청 창 직전 동일 길이(최소 15분)의 데이터를 실제
조회한다. 표본 부족 시 기존의 한 번 확장 규칙을 적용하고, 조회된 기준선이
비어 있을 때만 unavailable로 표시한다. 실행 날짜와 고정 3일 TTL로 조회를
미리 차단하지 않는다. 복원 DB와 라이브 DB에 같은 관측 기반 규칙을 적용한다.

확장 기준선 조회 실패도 오류로 전달한다. 실패를 빈 관측처럼 감추지 않는다.
기준선 창 좌표는 unavailable이어도 반환하고, 데이터가 없는 이유를 임의로
TTL 만료라고 단정하지 않는다. 현재 데이터가 없다는 사실은 수집 완전성의
증거가 아니며 normal은 기존 보수적 판정식의 결과다.

## MCP 사건 시각

rca-mcp의 -first-event/-last-event를 RFC3339로 받아 Toolset에 전달한다.
둘 다 생략하면 기존 라이브 기본값을 유지한다. 하나만 제공, 잘못된 값,
역전/같은 시각은 DB 접속 전에 거부한다. 케이스 runner는 seed의 t1/t2를
MCP 프로세스 인자로 JSON 직렬화해 전달한다. 상대 now의 전역 가상 시계까지
구현한 것은 아니므로 재현 호출은 명시적인 사건 시각을 사용해야 한다.

## 대상 발견

search_targets는 현재 연결 DB의 targets를 이름·표시명·UUID·주소의 리터럴
부분 문자열과 정확한 type으로 검색한다. limit 1..100, offset 페이지를
지원하고 UUID 및 pg:targets 참조를 반환한다. 매칭 총수를 추정하지 않고
하한·has_more·next_offset을 표시한다. 인벤토리 존재를 장애 관련성이나
과거 가용성으로 해석하지 않는다. 카탈로그와 runner가 이 시작 경로를 안내한다.

## 검증

- HTTP 가짜 CH에 2000년 캡처를 제공해 기준선 조회와 50배 지연 변화 검출 확인.
- 기준선 완전 부재, 확장 후 가용, 확장 쿼리 실패 분기 검증.
- PG 가짜 서버로 이름/UUID 검색, 인자 바인딩, 첫/마지막/빈/초과 페이지 검증.
- MCP 시각 형식·타임존·누락·역전 검증 및 runner 설정 경로/인자 직렬화 확인.
