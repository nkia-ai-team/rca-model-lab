관측과 자산을 연결

application의 host_target_id → server 직접 관계를 먼저 확인합니다. 시간창 내 트레이스·파드·노드로 추가 연결하며 간선은 앱 → 호스트 방향을 유지합니다.

프로세스·포트 추가 확인

get_process_snapshot
search_host_data(kind="connections")

트레이스는 지정 시간창, 파드 배치는 현재 자산 스냅샷 기준입니다. 과거 배치·미수집 서비스·전체 PID/포트를 보증하지 않습니다. 같은 호스트라는 이유만으로 서비스 간 호출 관계를 만들지 않습니다.
식별·모호성·조회 한도

직접 연결은 application → server 유형을 검증한 targets.meta.host_target_id를 사용합니다. 트레이스가 없어도 동작하며 시간 근거는 current_inventory;not_historical입니다. CH·파드 조회 실패 시 직접 관계는 보존하고 실패한 원천을 degraded로 표시합니다.

트레이스 경로의 서비스 UUID는 lucida.target_id로 확인합니다. 미확정 서비스는 service:<이름> 노드로 남기고 중복 파드/노드 이름의 모호한 연결은 제외합니다. hosted_on 탐색은 APM hop을 소모하지 않으며 기존 크기 제한·truncated 표기를 유지합니다.

시간 근거: span_in_window;pod_placement=current_inventory

원문 reader 없음

structured-v2원문 보관 + 필드·누락 정보전달된 v2 관측 봉투 유지read_observation

원문 reader는 해당 조사에서 발급한 observation_id만 허용합니다. JSON 필드 선택과 페이지 조회를 지원하며 임의 파일 경로는 받지 않습니다.

“원문”은 도구가 반환한 전체 응답입니다. DB 전체나 도구 내부 limit 밖의 행까지 저장하는 것은 아닙니다. 중요한 증거를 모델이 반드시 읽는다는 보장도 없습니다.

학습으로 이어지는 경로

교사 풀이 → 근거·기전 채택 → 필요 시 추론 재작성 → 학습 예제 → SFT

검증셋으로 체크포인트를 선택하고 봉인셋으로 최종 평가합니다. 현재 턴을 학습 단위로 삼는 것과 에피소드의 턴을 임의로 버리는 것은 다릅니다.

프롬프트 예산 0은 조사 제한만 해제합니다. 모델 서버의 입력+출력 컨텍스트 상한은 그대로입니다.

최신 소스와 제품 배포의 경계

소스 수정은 실행 중 평가 바이너리를 바꾸지 않습니다. 새 기능은 빌드·검증 후 새 바이너리 해시와 실행 이름으로 평가합니다.

Go MCP 도구는 제품에서도 재사용할 수 있습니다. 제품 연결에는 인증·테넌트/대상 범위·읽기 권한·취소/시간 제한·결과 계약 연결이 필요합니다. 이 저장소의 캡처 복원 실행기가 제품에 배포됐다는 뜻은 아닙니다.
