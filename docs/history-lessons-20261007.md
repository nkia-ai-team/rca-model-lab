# RCA 개발 시행착오와 재실행 방지 계약

작성: 2026-10-07. 저장된 기록의 확인 범위는 2026-08-20~2026-10-07이다. 과거 산출물 전체를 독립 재현한 보고서가 아니며, 사용자가 언급한 두 달의 모든 대화·실험이 빠짐없이 수록됐다고 주장하지 않는다. 본 감사에서 학습·서버·데이터는 변경하지 않았다.

## 계획의 계보

이번 실행은 [2026-09-08 병목별 후속 계획](../../rca-model-lab/.omx/plans/rca-v34-diagnostic-followup-20260908.md)을 계승한다. 당시에도 **정답 정합성 → 증거 전달 계약 → 충분성·문맥 비교 → 실패 상태 교정 → 보상이 신뢰 가능한 RL** 순서를 정했다. 새 문헌 조사로 이 계획이 처음 생긴 것이 아니다.

현재 필요한 일은 기존 게이트의 완료 여부와 MCP 파이프라인 적용 여부를 확인하고, 미완 항목을 구현·검증하는 것이다. 옛 하네스에서 수정됐다는 사실만으로 현재 MCP 경로까지 검증됐다고 간주하지 않는다.

## 폐기·수정된 설명을 재사용하지 않기

1. **09-17 “비정합 추론 때문에 loss가 오른다”**: 같은 날 정합 추론을 사용한 v1e도 실패해 발산의 충분한 설명으로 기각됐다. 추론↔행동 불일치라는 데이터 결함 자체는 별개로 남는다.
2. **09-18 “gradient는 정상이고 최적점 절벽·모델 둔감성이 원인”**: 10-02 base Linear 입력 gradient 단절 발견으로 철회됐다. 09-16 이후 수정 전 SFT/RL은 이 구현 결함의 영향을 받았다고 기록돼 있다. 따라서 reasoning weight0/.3의 과거 결과도 정상 trainer에서의 순수 인과 비교로 취급할 수 없다.
3. **09-09 “신서버 parity 미해결”**: 같은 날 이후 [결정 기록](../../rca-model-lab/docs/decisions.md)에서 서버 구성5요소 재현 후 cold20/20 정상·seed결정으로 갱신됐다. 초반 파일럿 문구만 인용해 현재 미해결이라고 하지 않는다.
4. **09-22 “평가 도중 바이너리 변경은 필드 추가라 무해”**: 저장 문서의 해석이며 무해성을 입증하는 통제 실험은 아니다. 이후 실험은 실행별 바이너리SHA를 고정해야 한다.
5. **증거를 인용했으므로 인과 추론을 잘했다**: 09-09 파일럿에서 직접 반례가 관측됐다. 출처 추적 성공과 원인 연결 성공을 분리한다.

## 이번 관측 기반 judge 작업의 최소 검증

- 현재 행동 이전에 모델에게 노출된 관측만 평가 문맥에 포함한다. 이후 도구 결과·정답·hint를 입력 근거로 섞지 않는다.
- 사실 원문, source view와 위치, 시간 경계, 생략 여부를 추적 가능하게 유지한다.
- 요약·잘림·누락 때문에 확인할 수 없는 판단은 근거 부족으로 남긴다. 부족을 모순이나 오답으로 자동 변환하지 않는다.
- 압축 전후 결정적 사실 보존과 실제 예산을 검사한다. 사실이 사라진 경우 원문 조회 또는 판정 불가 경로가 있어야 한다.
- 기존 판정 결과는 provider/model뿐 아니라 rubric·context policy·source view까지 일치할 때만 재사용한다.
- 학습용 grounding 품질 개선과 최종 RCA 성능 개선을 별도 성과로 보고한다. 이후 학습 비교는 하네스·데이터·loss 변경을 통제한다.

## 확인 범위와 남은 공백

주요 근거는 MCP 개발 원장, sibling rca-model-lab의 날짜별 진단 문서·결정 기록·09-08 계획이다. 문서에 연결된 모든 원격 W&B run, GPU 파일, 임시 scratchpad, 각 평가 원장을 전수 재현하지 않았다. 08-20 이전 기록, 문서화되지 않은 실패, 모든 채팅 기록까지 완전하게 감사한 것은 아니다. 옛 코드의 수정 완료 기록은 현재 실행 경로에 대한 검증을 대체하지 않는다.
