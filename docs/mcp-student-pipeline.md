## 학습 데이터·손실 계약

- 예제 = 어시스턴트 턴 1개. 프롬프트 = 그 시점까지의 대화에서 **이전 턴 추론(reasoning_content) 제거** + 생성 헤더. 롤아웃 때 서버에 이전 추론을 안 보내므로 학습 문맥을 똑같이 맞춘다 (에피소드 통짜 시퀀스는 추론이 끼어 61k 토큰, 창 49k 초과·분포 불일치).
- 완성 = `<|start|>assistant to=self<|message|>추론<|eom|><|start|>assistant to=<tool><|message|><atem:function_calls>…</atem:function_calls>`. 마지막 종료 토큰은 손실 제외 (템플릿은 `<|eot|>`, 롤아웃 문법은 `<|eom|>` 강제).
- 케이스 균형: 케이스별 총 가중치 동일 (에피소드·턴 수와 무관).
- 실측: 30턴 에피소드 = 31 예제, 15k~49k 토큰, 합 ~870k 토큰.

교사 궤적은 자동 채점(대상)만으로 채택하지 않는다. 채점자가 기전을 meta 와 대조해 `run<N>/review.json {"accepted": true|false, "note"}` 를 쓰고, export 는 `--require-review` 로 그것만 받는다 (f09-h v2 run2: 대상 맞고 기전 틀림 → 기각).

**힌트 궤적의 추론은 그대로 쓰지 않는다.** 힌트를 user 에 두든 system 에 두든 학생 추론이 피드백을 언급한다(f01-p: 28턴 중 15~22회 "Feedback says…"). 그래서 `scripts/mcp_rationalize.py` — 채택된 행동열은 그대로 두고, 각 턴을 **무힌트 문맥**(이전 추론 제거)에서 `muse_grammar.exact_call_request_fields` 로 그 도구·그 인자를 강제한 채 추론만 다시 샘플한다(STaR rationalization). 결과 `trajectory.rationalized.jsonl` 을 export 가 우선 사용(`--require-rationalized`). 교사(Claude) 행동열도 같은 경로로 학생 문체 추론을 얻는다.

학생 무힌트 롤아웃(학습 케이스)은 초반 12런 채택 0 — **첫 영향 서비스에서 멈추고 발원지까지 한 홉을 더 안 감** (transfer↔Oracle, order↔payment, 느린 쿼리 미끼). 학생 힌트 수집(`configs/teacher/hints-r1-student.yaml`, ① 오답 배제 + 의존 대상 검색)으로 성공 궤적을 확보하고 무힌트 프롬프트로 저장한다 — 우연히 맞춘 것만 모으지 않는다는 원칙.

## 2026-09-17 — 학습 loss 상승의 정체: 추론 항 vs 행동 항

v1(5e-5)·v1d(2e-5) 는 발산했고 v1c(1e-5, clip 0.5) 는 버티지만 loss·grad 가 단조 상승한다(step 178→226: loss 0.541→0.692, grad 1.04→1.37). 네 런 모두 같은 모양이라 하이퍼파라미터가 아니라고 보고, 학습 데이터에서 감독 토큰을 추론 구간과 호출 구간으로 갈라 NLL 을 쟀다 (vLLM `prompt_logprobs`, 36 예제 = 추론 12,069 토큰 / 호출 3,108 토큰).

| 모델 | 추론 NLL | 호출 NLL |
|---|---|---|
| 베이스 | 0.526 | 0.268 |
| v1c checkpoint-90 | 0.606 | 0.268 |
| v1c checkpoint-180 | 0.803 | 0.223 |

**학습 데이터인데 추론 NLL 이 오른다.** 원인은 v2 데이터의 추론이 호출을 모른 채 써져 행동과 불일치하기 때문(측정: 12턴 중 11턴). LoRA 가 "문맥 → 올바른 호출" 로 갈수록 그 문맥에서 엉뚱한 추론의 확률은 내려간다. 두 목표가 경합하고 행동 쪽이 이긴다. 즉 전체 loss 상승 = 발산이 아니라 **모델이 비정합 추론을 거부하는 신호**이며, 판정은 loss 가 아니라 체크포인트 검증 곡선으로 해야 한다 (checkpoint-90 이 베이스 초과: 6/12 vs 5/12).

대응은 이미 만든 두 가지가 맞다. ① 데이터 v3 — Claude 가 고정 호출을 알고 쓴 추론(판정 통과 턴만 감독)이라 두 목표가 같은 방향. ② `reasoning_loss_weight` 0.3 — 남은 문체 마찰을 줄이고 행동 토큰이 목적함수를 지배하게 한다. 학습 로그는 `objective/reasoning_ce`·`objective/call_ce` 로 두 항을 분리 기록한다(가중치가 1이 아닐 때).

## 2026-09-17 저녁 — v1e 실패, 절제 실험 v1f, 트레이너 누적 스케일 결함

- **v1e (데이터 v3 + 추론 가중 0.3) 실패.** checkpoint-60 검증 0.333/0.375 로 베이스(0.417/0.458) 이하, step ~130 에서 grad 5.5 스파이크. "비정합 추론이 발산 원인" 가설은 **기각** — 정합 추론(Claude)으로도 발산했고 오히려 더 일찍 왔다. 다섯 런 전부 발산: v1(5e-5) 78, v1d(2e-5) 125, v1c(1e-5) 261, v1e(1e-5, v3) ~130.
- **v1f = v1c 절제**: 데이터 v2·lr·LoRA 전부 동일, `reasoning_loss_weight: 0` (호출 토큰만 감독, 추론은 문맥으로만), save_steps 30. 안정하면 추론 감독이 원인, 그래도 발산하면 트레이너.
