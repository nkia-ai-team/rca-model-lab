- Config `data` is pinned per update at rollout start (`cur["data"]`): the local preparation used by run.py/finalize, plus the
  remote preparation, split and runtime used for training.
- An update already in flight keeps the legacy v2 values, so u2 trains on v2 with fast4; v3 starts at u3.
- Remote runtime `general-update-fast5-20261015` = fast4 + `validate_training_split` reading counts from the preparation.
  The sealed set must stay 12. Tested: new train cases accepted; validation, quarantine and sealed rejected; the v2 record still accepted.
- Eval track `validation10` (10 × 2 runs, contract v3) replaces the v45 six-case track, which held three f06-p captures of one
  scenario and two unassigned captures. The start policy is measured on validation10 once, before the first regular eval;
  the regression check uses validation10 together with that reference.
