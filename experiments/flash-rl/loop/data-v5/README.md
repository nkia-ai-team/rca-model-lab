## Eval robustness (2026-10-23, user: "original12 빠진 4케이스 다시 재서 기준점에 합치고, 루프에 터널 감시·실패 집계·실패 케이스 재시도도 넣어")
Cause: at 16:14 KST the KT proxy closed the SSH forward; loop.py only re-opened it when (re)starting servers, so the last 4
start-policy original12 cases (f06-r, f09-h, f11-r, f20-r) failed with "Connection refused", and the case runner's exit code 0
left them out of failed_cases (total quietly 16 instead of 24). Stop-gap: `tunnel_keeper.sh` (until the patch is installed).
Patch (in `loop.py.prejudge`, installed by apply_v5.py after milestone 39, offline-tested with mocked servers/runner):
- tunnel keeper thread (10 s) under a lock; a forward already listening on the ports is accepted.
- every eval case: unscored run dirs set aside as `runN.failed-<ts>` (responses.jsonl is appended to), up to 2 retries after a
  tunnel check, and a case still short of runs is a failed case (logged as FAILED).
- `repair_milestones()`: tracks of this epoch's milestone reference (start policy) and of the last milestone eval (while its
  policy is current) with missing cases are re-run into the same eval dir and re-totalled; servers go back to the current policy.
